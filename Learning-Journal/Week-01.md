## 🔌 Wednesday — API (1st October)

Topic: HTTP Overview
What I learned: Basics of HTTP

What I practiced:

Questions:
1. **In HTTP, who always starts the conversation?** - client always starts the conversation by sending a request to the server.
2. **What does it mean that HTTP is "stateless"?** -Stateless means there is no built-in link between one request and the next. Cookies are added on top to create sessions.
3. **Which mechanism lets a stateless HTTP system remember a logged-in user or shopping cart?** - Cookies, carried in headers, let requests share the same context, which creates sessions even though HTTP itself is stateless.
4. **Which HTTP version introduced multiplexing, sending many messages at once over a single connection?** - HTTP/2 which allows multiple requests and responses to be sent simultaneously over a single connection. HTTP/1.0 opened a new connection per request, HTTP/1.1 added persistent connections, and HTTP/2 added multiplexing.
5. **Which set correctly lists the parts of an HTTP response?** - 
   - Status line (HTTP version, status code, reason phrase)
   - Headers (key-value pairs providing metadata)
   - Body (optional content, such as HTML, JSON, or binary data)
